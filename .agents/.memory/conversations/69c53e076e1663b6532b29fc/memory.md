## Active build plan — hikari_market_keeper
Work through every step, and confirm each is satisfied before telling the user the agent is ready.

- [ ] 1. Create the five new entities — GameCompany (player entity: name, hikari_balance, assets_held_count, V_score, D_score, created_date, membership_tier), GameHolding (company_id, question_id, purchase_price_hikari, current_V, current_D, held_since), GameTransaction (buyer_id, seller_id, question_id, price_hikari, v_at_trade, timestamp, trade_type), GameEvent (event_type, question_id, description, impact_level, v_before, v_after, timestamp), GameLeaderboard (company_id, rank, v_score, d_reduction_total, resonance_score, period) — with relationships linking GameCompany→GameHolding→Question and GameTransaction→GameCompany.
- [ ] 2. Write operating rules to .agents/rules/closed-system-integrity.md, .agents/rules/v-formula-enforcement.md, .agents/rules/membership-gating.md, .agents/rules/no-financial-advice.md, and .agents/rules/trading-integrity.md so they are injected into every conversation automatically.
- [ ] 3. Create backend function execute_trade(buyer_company_id, seller_company_id, question_id, price_hikari): validate both companies' Hikari balances, enforce closed-system rules via enforce_closed_system, create GameTransaction, update GameHolding ownership, update both companies' hikari_balance, recompute V scores, and trigger leaderboard recalculation.
- [ ] 4. Create backend function calculate_idea_V(question_id): fetch Question's TAM value (N) and current implementation difficulty (D), compute V = N / D, return current V and the N/D breakdown for display.
- [ ] 5. Create backend function process_ipo_event(question_id): take a newly GO-judged Question from MorningHarvest, compute its initial V = N/D, create a GameEvent of type 'IPO', set it as available for trading, and return the IPO details for notification.
- [ ] 6. Create backend function reduce_D_via_research(company_id, question_id, research_payload): validate the research contribution is substantive (not empty/trivial), reduce D by a computed delta based on contribution quality, recompute V for that GameHolding, award Hikari to the researching company, create a GameEvent of type 'D_REDUCTION', and return the new V/D values.
- [ ] 7. Create backend function enforce_closed_system(transaction): validation gate — verify no Hikari is being transferred to an external system_id, verify no real-money amount is entering game value calculations, verify both parties are authenticated members, and return pass/fail with an audit log entry.
- [ ] 8. Create backend function update_market_cap(): iterate all GameHolding records, sum current_V across all held assets, combine with KnowledgeStandard TAM totals, persist updated total market cap to KnowledgeStandard, and return the new figure.
- [ ] 9. Create backend function get_market_overview(filters): return paginated list of all tradeable GO ideas with current V, D, last trade price, number of holders, and 24h change — the data behind the real-time market display.
- [ ] 10. Create backend function get_player_portfolio(company_id): return the player's GameCompany profile, all GameHoldings with current V/D, hikari_balance, V_score, D_score, and rank from GameLeaderboard.
- [ ] 11. Create backend function issue_hikari_reward(user_id, amount, reason, related_event_id): mint Hikari within the closed system for verified D-reduction, profitable trade closure, or research contribution; create a HikariTransaction with type 'game_reward' and source 'kokyaku_game'; update FanProfile hikari_balance; enforce that this does not violate closed-system rules (rewards are internally generated, not externally injected).
- [ ] 12. Create backend function check_membership_access(user_id): query FanProfile for membership_tier; verify the tier qualifies for game access (per the gating policy); return access decision and tier label for the UI.
- [ ] 13. Create backend function generate_leaderboard_data(): query all GameCompany entities, compute V_score (sum of held assets' current V), D_reduction_total (cumulative D reduced through research), and resonance_score (from HikariTransaction game_reward history); rank and persist to GameLeaderboard; return top N for display.
- [ ] 14. Authorize the Slack bot connector (slackbot) and configure it to operate in the #hikari-market channel for proactive market notifications and reactive @mention responses.
- [ ] 15. Set up the Slack channel integration: agent posts as its own bot identity in #hikari-market, responds to @mentions in-thread, and sends scheduled digests and high-impact event alerts.
- [ ] 16. Create the six automations listed above, wiring each schedule/entity-change/Slack trigger to its corresponding skill or backend function.
- [ ] 17. Create the ten skills listed below, each as a named playbook the agent follows when its trigger condition is met.
- [ ] 18. Build the in-app web interface pages: Market Overview (real-time idea prices and V scores), Player Dashboard (portfolio, balance, V/D scores), Trading Interface (bid/ask in Hikari), Leaderboard, and Market Event Feed (live IPO and D-reduction events).
- [ ] 19. Run an end-to-end test: simulate MorningHarvest injecting a new Question → verify IPO event fires → simulate a player trade → verify GameTransaction, GameHolding, and balances update → verify leaderboard recalculates → verify Slack notification posts.
- [ ] 20. Run a closed-system integrity audit: verify no function path allows Hikari withdrawal, external transfer, or real-money injection into game value; confirm all HikariTransaction game entries have internal sources only.
